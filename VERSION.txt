LeadGap AI – Local Business Opportunity Finder
Project release: 0.0.35d-observe
Actor definition version: 0.35
Date: 2026-09-21

Release candidate changes:
- Localized candidate-page discovery and booking signals for German, French, Spanish, Italian, Dutch and Polish sites.
- Added NICHE_RULES alias keys so Dental, Beauty, Salon, Legal, Attorney, Tax, Accounting and related short queries pass relevance filtering as well as qualification.
- Added common service-form aliases such as Plumbing, Roofing, Cleaning, Landscaping, Building and Electrical.
- Added a dedicated general Spa/Wellness relevance rule instead of mapping Spa to medical aesthetics.
- Added polite DuckDuckGo HTML throttling for repeated external website verification.
- Treat DuckDuckGo HTTP 202/challenge and empty unparsable result pages as UNAVAILABLE instead of false NOT_FOUND.
- Corrected README restaurant wording so it no longer claims dedicated menu/reservation scoring.
- Added appointment-specific `whyThisLead` copy.
- Improved contact-form detection using labels, ARIA hints and embedded form/booking providers.
- Added full locale `Accept-Language` headers with English fallback.
- Added `openingHoursDetailed` fallback.
- Hardened PPE push error handling while preserving Apify `charged_count` semantics.
- Kept `.actor` schemas and Apify SDK pin from 0.0.34.

Observability-only diagnostic build:
- Adds PLACE_INPUT per discovered Maps business.
- Adds PLACE_DIAG per processed/mismatched business with relevance, audit, signals, qualification and push outcome.
- Adds MAPS_FIRST_PLACE raw payload once per automatic run for upstream field inspection.
- Adds RUN_SUMMARY counters: discovered, after_dedup, after_relevance, after_audit, qualified, pushed, FOUND, NOT_FOUND, UNAVAILABLE.
- No commercial qualification, scoring, billing, niche, or discovery logic changed from 0.0.35d.
